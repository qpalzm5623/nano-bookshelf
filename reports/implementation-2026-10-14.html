남은 기능 구현 결과와 운영 연결 안내

최종 갱신: 2026-10-16 · Vercel + Postgres · 구현 커밋 e59e017a

회원·학급·배정·콘텐츠·포트폴리오를 관리하는 공통 서버 화면, 최초 완료 100P + 최초 생각담기 50P, 월별 랭킹, 첨삭 파일, 개인 설정 동기화와 학습 기록 이관 코드를 추가했습니다.

GitHub 푸시와 첫 운영 배포를 완료했습니다. API 실행 오류 수정 후 재배포 중입니다. 팀 식별자를 생략한 Vercel 커넥터 요청으로 프로젝트와 환경변수 접근을 확인했습니다. 기존 Postgres 연결을 확인하고 운영용 세션 서명 비밀키를 등록했습니다. 배포 빌드에서 추가 테이블과 비밀번호 해시 전환을 실행하도록 구성했으며, 첫 배포는 READY였으나 API 시작 시 500 오류가 확인됐습니다. Vercel이 사용하는 루트 TypeScript 설정의 ESM 출력에서 모듈을 찾지 못하는 오류를 로컬 재현했고, CommonJS로 통일하여 여섯 API의 컴파일 결과가 모두 로드되는 것을 확인했습니다. 재배포 후 운영 응답을 다시 확인합니다. 알림톡·결제 운영 정보가 없어 해당 외부 연동은 비활성 상태입니다.

실제 사용 흐름의 변화

영역구현한 동작확인할 점
운영 관리manage.html에서 본사·학원이 같은 화면과 API를 사용합니다. 기존 편집 버튼과 운영 메뉴가 이 화면으로 연결됩니다. 검색, 빈 목록, 저장 오류, CSV 내보내기, 모바일 메뉴와 키보드 초점을 제공합니다.학생은 관리 API에 접근할 수 없습니다. 교사는 배정·보유 도서·포트폴리오, 원장은 회원·학급까지, 본사는 가맹 학원·전체 콘텐츠를 변경할 수 있습니다.
회원·학급회원 생성/수정/퇴원, 승인/정지, 비밀번호 해시 저장, 학급 편성, 학원 정원 검사. CSV 1~200명 등록은 한 트랜잭션으로 처리합니다. 회원 수정 충돌은 덮어쓰지 않습니다.비밀번호 12~128자. CSV 등록 회원은 미승인 상태이며 보호자 발송 동의는 기본 해제입니다. 본사 계정은 이 화면에서 권한을 낮추거나 삭제할 수 없습니다.
도서·배정도서, 객관식 문항, 생각담기, 추천 여부, 테마 연결, 표지/학습지 HTTPS 주소, 학원 보유 도서와 개인/학급 배정을 저장합니다. 학생 화면도 DB의 도서·문항·배정을 조회합니다.문항이 없으면 임시 퀴즈를 만들지 않습니다. 문항 번호 중복을 거부하고 완료된 학습의 도서는 삭제하지 않습니다. 운영 콘텐츠 편집 권한은 본사에 있습니다.
포인트학생·도서별 최초 완료 100P, 최초 생각담기 50P. 나중에 생각담기를 추가하면 50P만 적립합니다. 회원 행 잠금과 고유 적립 ID로 중복 보상을 방지합니다.기존 DB 기록에 대한 소급 적립은 하지 않습니다. 로컬 기록 이관에도 새 포인트를 지급하지 않습니다.
랭킹·개인 기록한국 시간 월경계로 이번 달/지난 달 포인트를 집계합니다. 학생은 반·학원·전국 순위를 보고, 전국 다른 학생 이름은 가립니다. 포인트와 학습 내역을 페이지 단위로 끝까지 조회합니다. 찜·관심 주제는 서버에 저장합니다.다른 기기와 수정이 충돌하면 새로고침을 안내합니다. 새로고침·화면 진입 시 최신 데이터를 조회하며 실시간 푸시 동기화는 제공하지 않습니다.
첨삭 파일PDF/PNG/JPG를 Postgres에 비공개 저장하고 인증된 다운로드 API로 제공합니다. 같은 파일 재시도는 중복 저장하지 않습니다. 학생은 본인의 기록만, 교사는 소속 학원의 파일만 엽니다.파일당 2MB, 학습 기록당 10개. 파일의 실제 시작 바이트를 검사합니다. 파일 업로드와 첨삭 글 저장은 별도 단계이므로 글 저장 실패 시 이미 올라간 파일은 유지됩니다.
포트폴리오학생과 기간을 선택하여 실제 학습 도서·날짜·점수와 교사 총평을 저장하고 인쇄/PDF 저장 화면을 제공합니다. 수정 충돌 검사를 적용합니다.기존 예시 문해력 점수·임의 평가를 사용하지 않습니다. 발급 시점의 기록을 저장한 문서입니다.
공지·배너본사 서버 관리 화면에서 등록하고 학생/학원 화면은 최신 DB 자료를 읽습니다. 공지는 대상 권한을 구분하고, 활성 배너만 표시합니다.배너 이미지는 HTTPS 주소를 사용합니다. 상단 고정 공지는 팝업으로도 표시합니다.
로컬 기록 이관학생 화면 상단에서 본인 기록을 JSON으로 먼저 내려받은 후, 확인을 거쳐 서버 문항으로 재채점합니다. 완료 기록 ID 재시도를 처리하며 오류 내역은 따로 내려받습니다.원본은 삭제하지 않습니다. 서버 문항과 다른 기록은 자동으로 강제 이관하지 않습니다. 로컬 회원·콘텐츠는 CSV 또는 운영 관리 화면에서 검토 후 등록해야 합니다.
알림톡환경변수가 준비되면 수신 동의·번호를 검증하고, 리포트 내용과 수신자를 확인한 뒤 Aligo API에 요청합니다. 같은 내용의 중복 요청과 결과 불명 요청의 자동 재발송을 차단합니다.ACCEPTED는 발송 요청 접수이며 최종 수신 성공이 아닙니다. 최종 결과와 결과 불명 건은 알리고 관리자에서 확인합니다. 이번 작업에서는 실제 전송하지 않았습니다. Aligo 공식 API 문서
결제설정된 업체의 HTTPS 결제 안내 페이지로 진입하고, 본사는 실제 확인한 입금을 기록합니다. 같은 등록 요청 재시도를 중복 입금으로 기록하지 않습니다.업체가 정해지지 않아 자동 과금·정기결제·웹훅 검증·자동 계약 갱신은 연결하지 않았습니다. 결제 주소만 설정해도 이 기능들이 자동 활성화되지는 않습니다. 임의 결제 성공 처리는 사용하지 않습니다.

운영 연결에 남은 작업

  1. Vercel 접근: nano-bookshelf 프로젝트 상세와 환경변수 조회 성공. 로컬 프로젝트 연결 정보도 등록했습니다.
  2. 환경 확인: 기존 DATABASE_URL과 비풀링 연결을 확인하고 운영 PORTAL_AUTH_SECRET을 등록했습니다. DIRECT_URL이 없으면 DATABASE_URL_UNPOOLED 또는 POSTGRES_URL_NON_POOLING을 사용합니다. 환경변수 예시에는 이름과 용도를 정리했습니다.
  3. 추가 테이블: 운영 빌드의 scripts/prepare-portal.cjs가 portal-upgrade.sql을 적용합니다. 개인 설정·포트폴리오용 portal_settings, 비공개 첨부용 portal_files를 추가합니다. 기존 테이블 삭제나 초기화는 포함하지 않습니다.
  4. 운영 계정: 로컬 설정이 가리키는 DB에서 기존 평문 비밀번호 2,194건을 확인했습니다. 운영 빌드가 기존 입력 비밀번호를 유지하며 scrypt 해시로 전환하고 승인된 본사 계정을 확인합니다. 이미 전환된 계정은 다시 변경하지 않습니다. 계정 초기화가 필요한 경우 scripts/set-portal-password.ts를 사용합니다.
  5. 배포: 빌드 npm run build, 출력 dist. API는 portal, bootstrap, manage, activity, files, services가 필요합니다. 운영 빌드는 전체 회원 덤프와 PHP 서버 설정을 제외하고 인증 후 데이터를 가져옵니다.
  6. 실제 사용 확인: 별도 학생/교사 계정으로 로그인 → 배정 → 퀴즈 제출 → 150P 확인 → 재풀이 중복 적립 없음 → 다른 기기 첨삭/첨부 → 포트폴리오 인쇄를 확인합니다. 현재 검증은 로컬 자동 테스트이며 실제 DB·브라우저의 종단 간 검증은 아직 하지 않았습니다.
  7. 외부 서비스 활성화: Aligo 승인 발신 프로필·템플릿과 API 설정 후 ALIGO_ENABLED=true로 전환합니다. 결제 업체가 정해지면 해당 업체의 결제 생성·서명 검증·환불/갱신 흐름을 추가 연동해야 합니다.

프로젝트와 환경변수 확인을 완료했습니다. 운영 빌드는 필수 환경변수·스키마·본사 계정 검사에 실패하면 중단됩니다. 빌드 중 DB에 적용된 추가 테이블과 비밀번호 해시는 이후 빌드가 실패하더라도 유지됩니다.
